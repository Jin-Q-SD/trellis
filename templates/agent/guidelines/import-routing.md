# import 整理规则

`import/` 是用户随手丢文件的地方。用户把文件丢在根目录也可以，agent 会先把它们移进 `import/`。

## 什么时候检查

- 每次会话开始时看一眼 `import/` 和根目录。
- 用户提到"整理"、"我放了个文件"、"刚丢进去的"之类的时候。
- 用户说 `/trellis tidy` 时。

只读的体检可以用 `python3 agent/tools/scripts/scan.py .`。

## 根目录白名单

根目录只允许以下内容，其他东西一律先移进 `import/`：
- `AGENTS.md`、`CLAUDE.md`、`README.md`
- `agent/trellis.json` 里 `dirs` 列出的目录，以及 `agent/`、`import/`、`_delete/`
- 隐藏文件和目录（`.git`、`.claude`、`.gitignore` 等）

## 处理流程

1. 打开或预览每个文件，判断它是什么。不要只看文件名猜。
2. 按 [naming](naming.md) 重命名，按下面的分发表移到对应位置。
3. **拿不准的**：只重命名，留在 `import/`，登记进 `import/README.md` 的"待确认"表，写上你的猜测。所有问题攒成**一条消息**一次问完。
4. 用户回答之后再移走，并从待确认表里删掉对应的行。
5. 把"原名 → 新路径"表写进当次会话的 memory（"文件整理记录"一节）。用户以后问"我上次丢的那个文件去哪了"时，靠这张表找。

## 分发规则表

| 文件是什么 | 去哪 |
|---|---|
| 论文、报告、文章、竞品资料、数据集等外部原始资料 | `research/sources/` |
| 访谈记录、调研笔记 | `research/notes/` |
| 需求文档、客户简报、合同要点 | `docs/brief/` |
| 用户自己写的文稿、草稿 | `docs/`（按主题建子目录） |
| 视觉参考、截图、情绪板 | `design/references/` |
| logo、字体、图片素材、品牌包 | `design/assets/` |
| 设计源文件（.fig、.psd、.sketch 等） | `design/`（按主题建子目录） |
| 代码、代码片段、资源包 | 应用目录里对应的位置；放不准就问 |
| 某个工具的配置、脚本、提示词 | `agent/tools/` 下对应的位置 |
| 用户给 agent 的规则或偏好说明 | 内容提炼进 `agent/guidelines/`，原文件按删除规则处理（先问） |

目标目录还不存在时，按约定新建，并补进目录地图。这张表可以根据项目调整，项目里出现新的文件类型时就往里加一行。

## 边界情况

- **只重命名 `import/` 里的文件**。其他地方的文件改名要先问用户，因为可能会打断文档链接或代码引用。
- **重名或内容重复**：不覆盖，先问用户。可以用 `shasum` 比对内容。
- **压缩包**：默认不解压，先问用户。
- **文件夹**：作为一个整体判断去向；它内部的文件名不逐个改，除非用户要求。
- **超大文件**（大于 500MB）：提醒用户，问它是否应该放在项目外面。
